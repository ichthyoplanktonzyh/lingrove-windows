# Canonical notebook export

This module adapts committed macOS `3b53402f2cbc196b0398d133177fd80006d165b2`: `Lingrove/Services/Vocabulary/VocabularyArchive+Export.swift`, `VocabularyExportSession.swift`, `Lingrove/Models/Vocabulary/VocabularyExportModels.swift`, `Lingrove/Support/Vocabulary/VocabularyExportPolicy.swift`, `VocabularyExportFormatter.swift`, `VocabularyExportZIP.swift`, `Lingrove/UI/Vocabulary/VocabularyExportSheet.swift`, `VocabularyNotebookView.swift`, and `LingroveTests/Services/Vocabulary/VocabularyExportTests.swift` / `LingroveTests/UI/Vocabulary/VocabularyExportAcceptanceTests.swift`.

The single canonical Store captures exact selected collected entry/sense IDs, selected semantics and classification, and referenced image bytes within its serialized storage span. A stale or missing offered sense fails with `Changed`; it is never replaced by a broader selection. The owned package supplies the same preview and saved bytes after notebook edits. Its 64 MiB document and 128 MiB image budgets, 192 MiB ZIP ceiling, Windows identity-bound atomic destination publication and media-v8/notebook protection are separate from backup. The scope/format/content controls are window-owned; selected IDs survive filtering and can be offered by the existing sense selection UI. The detail action offers one exact sense. Native destination selection is explicit and closing drains admitted work.

The canonical projection preserves source Double dates until output, nullable language, examples, authored content, optional fields and the version 1–5 semantic/classification rules. JSON and CSV use the source ISO8601 second-precision export representation, which is an output representation rather than a notebook conversion. A date outside the Windows calendar range fails visibly instead of silently changing the stored value. TXT/CSV carry selected semantic values; JSON carries selected full semantic and classification values including current guidance. Export is learning material, not a full notebook backup, and deliberately excludes review bindings and raw uncollected evidence as the source does. Complete recovery uses the separately documented backup operation.

The existing ZIP, destination picker and bounded save effects are reused; the old entry-owned export model and DateTimeOffset graph are not. Windows uses WPF native controls and the app theme. Local checks exercise real isolated SQLite, media ownership, exact selection, immutable package after later edit, protected destination, UI preview and retirement. The latest Mac source was read from Git; no native 3b Swift execution or physical Shell/desktop acceptance is claimed here. Extremely out-of-calendar SourceDate formatting is a documented Windows limitation; the durable canonical graph remains unchanged.
