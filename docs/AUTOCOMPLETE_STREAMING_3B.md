# Autocomplete streaming and continuation (3b53402)

This module adapts macOS commit `3b53402f2cbc196b0398d133177fd80006d165b2`: `Lingrove/App/Coordinators/Suggestion/SuggestionCoordinator+Prediction.swift`, `+TypingPrediction.swift`, `+Continuation.swift`, `+Acceptance.swift`, `+WordCompletion.swift`, `Lingrove/Support/Suggestion/Streaming/`, `Lingrove/Support/Suggestion/Session/SuggestionContinuationPlan.swift`, and `Lingrove/Support/Spelling/WordPrefixIndex.swift`. The corresponding streaming, word-prefix and coordinator tests in `LingroveTests` are the behavioral reference. Existing historical fixture pins are unchanged.

The existing coordinator owns generation, a coalesced latest partial, exact field/epoch checks, typing-candidate deadlines and acceptance. Final output supersedes queued partials; a cancelled or stale request cannot revive the overlay. Output is normalized and checked at the live seam before display. The single-word option buffers completed following words and accepts only the visible chunk. The local-only continuation path uses the same engine owner and clipboard snapshot, and waits for the expected host field before presenting. Endpoint requests never receive hypothetical continuation context. The existing router and native runtime serialize actual inference; shutdown cancels and joins admitted tasks, including prior work that ignores cancellation.

The prefix index is built off-thread with the existing spelling dictionary cache. Its bounded lookup and local fallback use unique document/glossary matches first, then a sufficiently dominant dictionary candidate; a cold index or ambiguity abstains. Windows continues to reject truncated fields where its insertion contract cannot prove the target. Native UTF-16 and UI Automation freshness checks are retained rather than changing record identity or reconstructing host edits.

The settings use the source keys and defaults: `lingroveStreamSuggestionsWhileGenerating` false, `lingrovePredictAheadWhileTyping` true, and `lingroveShowFollowingWords` true. General and Appearance expose these through the existing settings owner; no new model or endpoint owner is created. Local and endpoint partial callbacks feed the same normalization and admission path. Endpoint SSE has bounded lines and cumulative output.

Verification uses synthetic focus, insertion, local inference and HTTP boundaries: coordinator races and coalescing, final/partial ordering, hidden words, typing and host publication, local-only prefetch, work drain, source word-prefix/fallback decisions, settings persistence and fake endpoint streaming. The full solution compiles on Windows. No actual model, endpoint, user editor or clipboard was exercised. Physical desktop behavior, UI Automation host-specific timing, IME interaction and native model-backed streaming remain for the final user acceptance pass. Windows rejects unsafe or truncated captures, so this is a deliberate platform safety boundary, not a claim of identical host support.
