## Implemented boundary

`Core/Vocabulary/EntryInput` is an independent value-only parser and validation boundary. It admits CSV/TXT up to 4 MiB, UTF-8 or BOM-marked UTF-16, quoted CSV, physical line numbers, the original aliases/defaults/ambiguous translation rule, explicit mappings and bounded normalized form values. A cancellation token follows decoding and row mapping. The input has no durable IDs; it is not a Store, preview of notebook changes, import transaction or UI. Resource and existing historical fixture pins are unchanged. `VocabularyWordListException` exposes the source failure category and optional line; presentation must localize the corresponding Mac messages before exposing them to users.

The new Core cases port the frozen parser examples and add the explicit example-translation ambiguity, numeric-kind rejection, validation and cancellation. Native Swift parity execution has not been performed on this Windows host. The TXT line reader follows Foundation line terminators, including NEL, Unicode line and paragraph separators, and CRLF; normalized tags use Swift-compatible scalar order. Native Swift execution remains a cross-platform regression gate. No claim is made about archive behavior or full feature parity.

## Frozen UI audit and pending integration

The create sheet owns a draft, defaults source language to English and type to word, focuses expression on appearance, and has grouped expression/language/type/dictionary and meaning/meaning-language/notes/tags fields. A secondary note explains append-only behavior. Its 620 × 590 sheet has a headline, separators and 16-point footer with Cancel and prominent Save. Empty normalized expression disables Save; saving disables fields, Cancel and interactive dismissal; errors remain visible. Save waits for the shared Store and returns the exact sense selection; Cancel makes no write.

The 900 × 760 import sheet has a headline and file name, two explanatory lines, language/type/meaning-language defaults, CSV header and column controls (expression, meaning, example, translation, with other fields disclosed), preparation indicator, result counts and a table capped at 50 displayed rows, followed by failure, Cancel and prominent Import. A configuration change cancels old work, clears preview and error, and accepts only the current generation. Import is disabled during preparation/save or without changes; saving blocks dismissal. Commit re-evaluates through the shared Store, not stale preview counts. The import sheet requires actual archive preview/commit APIs; it is intentionally not connected to the older entry-owned Store or a temporary replacement here.

The frozen notebook defaults to list/entry organization, compact density, standard text size and visible categories. Toolbar list/graph switch is 164 points wide; Add and Import have Command-N and Command-Shift-I shortcuts on Mac. The empty entry notebook offers both actions. Successful additions clear search/language/tag filters, return to entry list, expand and select the acknowledged sense. Meaning organization filters by semantic node and category membership; category selection, meaning/sense selection and graph focus reconcile when data changes. The meaning sidebar uses hierarchy, selected/compact and detailed rows; the category sidebar has search, hierarchy, counts, editing and selection. Meaning detail uses a 28-point bold heading, 18-point definition, secondary scope and mapped entries with action controls. The category manager is 560 × 460. These are source observations and backlog, not implemented claims for the frozen UI.
