# Canonical notebook window lifetime

Reference: Mac `35b7fbe5c788c5524936ade1dfb7c89a3a285b04`, `Lingrove/Services/Presentation/VocabularyWindowController.swift`, `Lingrove/UI/Vocabulary/VocabularyNotebookRoot.swift`, and `VocabularyNotebookView.swift` (`revealAddedEntries`). The controller owns a single lazy window; the Store, bounded file reader and list-density preferences are borrowed from the app composition root. `Show()` alone creates and activates the window. Ordinary close hides it; reopening without a selection preserves its query, filters, navigation and disclosure state. Explicit `Show(selection)` clears the filters that could obscure the target and selects the exact collected entry/sense, even on cold load. While an input sheet is attached, the latest explicit selection is deferred until that sheet closes rather than replacing its draft. The sheet's result still uses acknowledged IDs. Initial and later display-language preferences choose existing labels; density reads/writes the existing `IVocabularyNotebookListPreferences` without applying model settings.

`DisposeAsync()` closes Show admission once, requests child-sheet retirement, waits accepted creation/import writes, cancels and drains all input preparation work (including retired previews), drains notebook reads and pending window operations, then unsubscribes and closes the window. The controller never disposes the borrowed Store or reader. Callers must await this operation while the WPF dispatcher is running before disposing the single backend; an already stopped dispatcher with a live window is reported as an error, not a successful drain. A native OpenFileDialog cannot be programmatically dismissed by this adapter; if a Shell picker is already active, retirement waits for it to return. Ordinary close requested during a modal is deferred until the modal finishes. Even after a user cancels and the modal disappears, the parent retains its drain until late reader and preview operations return; concurrent retirement calls share one completion. The input sheets keep cancellation and successful acknowledgement semantics; no new persistence owner exists.

This checkpoint does not compose AppHost, tray, writing-card navigation or the production Store, and does not activate a data file. Graph, editing, review, export, image display, speech and dictionary remain deferred as recorded in `VOCABULARY_NOTEBOOK_FROZEN_UI.md`. Fixed white/black and basic native controls remain a visual gap; dark and high-contrast adaptation, physical focus/activation, native Shell behavior and accessibility acceptance are not established by these tests. The user has excluded old Windows/macOS data compatibility from the campaign; no old file is read or converted here.
