# Vocabulary row JSON

This slice adapts the pinned Mac row-leaf codec. It supplies no database file, durable Save receipt,
archive import/export, media access or notebook UI. A decoded leaf must still pass relational
reconstruction and whole-graph admission before an archive can publish it.

The behavior reference is Mac commit `43ba08833a4b373b9b82bd4b4fc168ee18c3cd6f`:

| Mac source | Windows boundary |
| --- | --- |
| `Cotabby/Models/Vocabulary/VocabularyDatabaseModels.swift`, `Payload.encoded` / `Payload.decode` | `Core/Vocabulary/VocabularyPayloadCodec.cs` |
| Codable stored fields in `Models/Vocabulary`, `Models/Review`, `Models/LanguageLearning` | Existing immutable Core vocabulary/review/learning values, codec-only metadata and converters |
| `Cotabby/Support/Vocabulary/VocabularyDatabaseProjection.swift` | Existing typed row projection used to construct reference leaves |

`VocabularyPayloadCodec` is stateless. Its caller supplies the table to choose a typed leaf and gets
bytes or a fresh immutable value. It never infers a different table or adds a tagged union envelope.
Source field names retain `ID` suffixes and `appBundleIdentifier`; UUIDs encode uppercase, dates are
numeric seconds since 2001-01-01 UTC, absent optional fields remain absent, and nonoptional fields
remain required even where a constructor has defaults. Computed UI projections are excluded.

Swift associated content cases retain their `text` / `image`, `_0` and caption structure. Enum-keyed
maps use alternating key/value arrays, string-keyed maps use objects, and audio sets use arrays.
Enum tokens use exact source names and language codes. Unknown object fields are ignored. Duplicate
object keys use the first canonical spelling/value, including canonically equivalent string-map
keys; repeated enum-map keys instead use the final assignment. No literal text normalization occurs.

Encoding emits UTF-8 without a BOM. Actual Mac decoder probes cover UTF-8 BOM, UTF-16LE/BE with and
without BOM, unmarked UTF-32LE/BE and UTF-32BE BOM. The pinned decoder rejects UTF-32LE with BOM;
its observed `FF FE` precedence is retained. Invalid byte sequences, required-field/union failures,
wrong enum tokens and impossible .NET-only null nodes return `InvalidArchive`, without payload text.
The pure codec imposes no per-row byte budget. The source's 64 MiB SQLite value limit belongs to the
future storage adapter; an after-serialization size check would not be an allocation guard.

The date adapter preserves .NET UTC ticks on local roundtrip. `DateTimeOffset` covers years 1–9999
at 100 ns precision; Foundation `Date` stores a Double with a wider range and different precision.
Sub-tick numbers round to the nearest .NET tick, and unsupported dates fail rather than being clamped
or replaced. These limits, differing JSON key/set ordering and escaping, and incomplete storage
migration mean this is not a claim of byte-identical JSON or complete Mac archive compatibility.

The fourteenth Swift verifier compiles original pinned values and the complete original typed
payload methods. It borrows only fixed input construction from the projection driver. Forty actual
observations record native input bytes as base64, successful re-encoded JSON and identities/dates,
or native decode failure. C# consumes those bytes and compares JSON values; expected observations
are never generated by C#. Standalone tests additionally cover rich graph roundtrip, multiple audio
kinds, required-field deletion, null unions, malformed Unicode and .NET date limits. Existing fixture
expectations remain unchanged.

```sh
DOTNET_ROOT="$PWD/.dotnet" .dotnet/dotnet test tests/Cotabby.Core.Tests/Cotabby.Core.Tests.csproj --configuration Release
python3 scripts/verify-vocabulary-codec-macos-parity.py --mac-repo /path/to/macOS-lingrove
```

publication, media lifetime and Save/notebook UI remain migration work.
