# Canonical notebook explanation and dictionary

Reference: Mac commit `3b53402f2cbc196b0398d133177fd80006d165b2`, `Lingrove/Services/Vocabulary/VocabularyNotebookSession.swift`, `Lingrove/UI/Vocabulary/VocabularyExplanationSection.swift`, `VocabularyDictionarySection.swift`, `Lingrove/UI/InlineFeatures/LearningExplanationView.swift`, `Lingrove/Models/LanguageLearning/LearningExplanationModels.swift` and `Lingrove/Support/LanguageLearning/LearningExplanationPolicy.swift`; source-derived tests are not Swift executions.

The canonical window borrows the one application explanation service, dictionary and lexical providers through `FrozenVocabularyWindowController.AttachLearning`. Each usage UUID and supported standalone meaning owns a child session. Selection restores matching saved records without generation, activating one row cancels siblings, and navigation/hide retires unfinished work. Acknowledged adoption uses the same canonical Store; no secondary archive or model runtime is created. Explanation rows preserve authored wording and make generated replacements explicit. Dictionary lookup is an explicit disclosure; unknown source language uses root-locale segmentation and the existing unknown-language bundled provider.

The production local explanation engine uses the 3b current prompt. The historical `Prompt` entry and its old fixtures remain pinned. Explanation input retains optional language and unknown context; source absence does not imply English. SourceDate and canonical identifiers stay in the Store. Records whose dates cannot be represented by the current live Windows record are retained in the Store and shown with an explicit unavailable notice rather than rewritten. Provider changes and window retirement cancel presentation; Store operations already admitted are joined on shutdown.

Fake-driven tests exercise a real in-memory canonical Store, nullable source, stable usage/date, explicit generation and adoption, independent standalone/usage sessions, unknown dictionary routing, uncooperative late generation, and a rendered WPF component. They do not run native models, user editor access, real clipboard or external endpoints. The available dictionary remains bundled only; imported/system/online providers are unported. Physical desktop, screen reader, high DPI and model/GPU acceptance remain open. AppHost now calls the controller's `AttachLearning` with the shared service, dictionary, lexical adapter, root-locale word callback and configuration action. The attachment is inert until the notebook window exists; it creates no second service or Store. Writing enrichment also accepts the upgraded nullable input, while captures that explicitly disallow enrichment retain that guard.
