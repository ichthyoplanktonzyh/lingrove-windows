`VocabularyEntryCreationWindow` owns an unsaved form and submits validated values, including split tags, through an injected owner. `VocabularyWordListImportWindow` and its dispatcher-owned session borrow `IVocabularyWordListReader` for bounded file admission and own configuration, preview generation, and cancellation lifetime. `WindowsVocabularyWordListReader` follows links, inspects the opened handle for disk type, regular-file status and size, then reads at most 4 MiB plus one byte with cancellation. An opened handle retains the admitted file across path replacement; growth is rejected by the decoder. CSV mappings include the source defaults, examples and translation ambiguity resolved by Core; the preview shows at most 50 input rows and the actual owner-provided counts. The owner returns its preview revision and must preview the immutable inputs against a real Frozen document. Composition must forward Store revisions through `OwnerRevisionChangedAsync`; old generation completions cannot replace current state, including changes during preparation. Accepted commits are not cancelled on window close; dismissal is disabled while awaiting acknowledgement. `AddEntriesAsync` must re-plan atomically against the current document, return real counts and stable entry/sense selection IDs, and acknowledge durable publication. No owner implementation, second Store, temporary persistence or production command activation is included here.
