# Reading sources and context

Reference: Mac `3b53402f2cbc196b0398d133177fd80006d165b2`, `LearningReadingCoordinator.swift`, `LearningReadingSourceReader.swift`, `LearningReadingSelectionReader.swift`, `LearningVocabularyContextReader.swift`, `LearningReadingVisualReader.swift`, `LearningRegionSelectionPanel.swift`, `WindowScreenshotService.swift`, `LearningReadingTargetPolicy.swift`, `LearningReadingContextPolicy.swift`, `LearningReadingLookupPolicy.swift`, `LanguageLearningSettings.swift`, `SuggestionSettingsModel.swift`, and their reading/coordinator/OCR tests. C# regressions are source-derived; they are not Swift executions.

The candidate keeps one existing read-only UIA owner, translation owner, explanation owner and application hook. Selection, pointer and screen-region shortcuts default off and have independent per-app grants; the selection icon defaults off and supports an inherited per-app override. Shortcuts and grants are discoverable in Settings. The observation-only mouse owner has no UIA or synchronous UI work in its hook. A drag or double-click settles for 150 ms, captures one selection receipt without surrounding context, and does not invoke a model. Clicking the nonactivating icon or using the selection shortcut consumes that same receipt. If its capture is already in progress the shortcut waits for it rather than starting another capture. Context is read only after explicit activation; [the bounded context contract](READING_CONTEXT_3B.md) describes its 180 ms deadline and exact occurrence checks.

Pointer capture retains a real UIA range from the frozen physical point. This Windows subset requires the hit element to match the focused positively clear TextEdit element, verifies the nonsecure path and real range geometry, and revalidates occurrence, text, foreground, process and window frame. Unsupported providers are rejected; a failed UIA lookup does not trigger a screen or clipboard fallback. Pointer context uses the same bounded occurrence reader. No unknown language is replaced by English.

An explicit screen-region command obtains a guard for one nonsecure, positively clear focused TextEdit with a real same-process native HWND whose rectangle exactly matches the UIA element. The nonactivating picker is confined to that field and closes before any pixel capture. The selected integer crop must fit the field and one display, be at least 4 by 4 pixels, and contain at most 16 million pixels. One GDI capture checks the retained guard, host and field frames and visible intersecting HWNDs before and after the copy; a failed or uncertain check discards the data. It rejects intersecting visible child HWNDs other than the target and its ancestors, and intersecting visible top-level HWNDs above the host. Windows OCR runs locally and only after that explicit gesture; no language package is installed automatically. Missing OCR support reports a Windows settings action. Pixels are request-owned, cleared after use or retirement, and never persisted. OCR work and late native calls are joined; a late result cannot start a second request. The screenshot receipt carries its own field/display/region evidence and never invents a selection range or write authority.

The HWND checks are deliberately conservative and do not prove the absence of every DWM/GPU or windowless overlay or eliminate every cross-process race. A screen field must be the host HWND or its verified child, and a child must be observed in enumeration. Controls without a verifiable native field HWND, reliable UIA text/composition evidence, matching bounds or unobscured geometry remain unavailable. Arbitrary display regions and visual fallback for unsupported pointer/selection providers remain gaps. Native IME, mixed-DPI selection, actual Windows OCR language availability, physical Word/Chrome/Codex behavior and desktop visual/accessibility acceptance remain unverified. No user screen, editor, clipboard, real model or network is used in the component tests. After any in-flight OCR finishes, the adapter clears its writable WinRT input buffer and SoftwareBitmap before release; the GDI DIB is cleared before deletion. Copies internal to Windows OCR or the graphics system are not owned or erasable by this application.

The card continues to disclose the actual selected task destination before model work. Contextual basic meaning and full sentence translation remain separate, and accepted details are attached to the same capture and saved through the existing canonical Store, both when the favorite precedes details and when it follows them. Final effects retain the synchronous native-live permit; completed Store operations drain. Optional, content-free performance observations wrap the real reading translation and OCR calls with request identity, captured model/provider name, timing and outcome; they contain no selected text, prompt, region or pixels.

The app composition root must supply the existing native reader to `NativeReadingScreenReader`, one `WindowsReadingOcr`, the existing metrics sink and one `ReadingPointerMonitor`; it attaches those through `ReadingApplication.AttachScreen`, `AttachPerformance` and `AttachPointer`, and retires reading before disposing the mouse owner. Until that composition is reviewed and integrated this document describes the candidate rather than a shipped feature. WPF uses Segoe UI and a small nonactivating Windows-style icon; pixel equality with macOS is not required.
