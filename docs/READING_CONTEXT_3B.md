# Bounded selected-text context

Reference: Mac `3b53402f2cbc196b0398d133177fd80006d165b2`, `LearningVocabularyContextReader.swift`, `LearningReadingSelectionReader.swift`, `LearningReadingTargetPolicy.swift`, `LearningReadingContextPolicy.swift`, `LearningReadingLookupPolicy.swift`, and their target/context tests. The C# cases are source-derived, not executions of Swift.

The existing retained UIA owner acquires optional context from clones of the already selected range, after an explicit reading action consumes the receipt. A passive selection gesture does not read surrounding text. It never searches for matching text. Each COM stage checks the request permit and a single 180 ms deadline; a slow call cannot be interrupted, and its owner remains tracked. The selected range, text and positive composition evidence are checked before and after acquisition. The adapter accepts at most 3,072 UTF-16 units in the selection and 1,024 units of surrounding text. UIA character moves may be promoted by providers to larger units, so returned text and endpoints are bounded and independently checked. Only Edit control document edges establish container boundaries; other node edges remain unknown. Missing or late context does not invent a sentence or discard an otherwise verified selection.

Core aligns only an already anchored occurrence using source-equivalent NFC and whitespace rules, replaces it with authoritative selected code units, recomputes the range and detects introduced line breaks. Resolution uses injected sentence spans; Windows supplies the existing ICU root-locale tokenizer when no language has been identified. The final context target must exactly match the trimmed selection in UTF-16; canonical or whitespace equivalence is never used as final authorization. Nearby repeated text is not searched. Unicode and sentence tokenizer differences between ICU/Windows and Darwin remain unverified.

Contextual basic lookup favorites preserve the selected receipt UUID, exact context range, process-origin label, capture time, source completeness (sentence, fragment or unknown) and accepted full-sentence translation. The accepted target meaning remains separate. The canonical Store owns the resulting acknowledged capture. No detector is supplied and unknown source remains unknown. The [source candidate](READING_SOURCES_3B.md) documents details persistence, the bounded pointer/icon and explicit screen-region paths, composition still needed in AppHost, and remaining native gaps. This stage is not full reading parity.

Platform references: [UIA text ranges](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nn-uiautomationclient-iuiautomationtextrange) and [MoveEndpointByUnit](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.text.textpatternrange.moveendpointbyunit?view=windowsdesktop-10.0). Tests use synthetic text, fake races and an owned hidden RichEdit; they do not read a user editor, clipboard or screen, or call a model or network. Physical host/UIA and IME acceptance remain open.
