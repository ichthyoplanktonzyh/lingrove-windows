# Welcome readiness at 3b

Reference: macOS `3b53402f2cbc196b0398d133177fd80006d165b2`, `Lingrove/UI/Onboarding/Welcome/WelcomeReadinessView.swift`, `Lingrove/Support/Onboarding/OnboardingSetupPolicy.swift`, and `LingroveTests/Support/Onboarding/OnboardingSetupPolicyTests.swift`. Four rows offer autocomplete, translation, explanation and speech configuration, with real settings navigation. Downloading takes precedence over an absent or available selection. Configured means a selected valid configuration, not loaded or warm weights.

`WelcomeReadinessView` freezes task settings and assignment identities on the dispatcher, then borrows the existing model managers and bounded GGUF metadata reader on a worker. A new settings or admitted transfer event cancels and retires the previous scan; a stale result cannot publish. It checks general-instruction metadata for local explanation, URL/model structure for endpoint profiles, and the same speech asset validation used by synthesis. It reads no credential, enumerates no system voice, starts no model, download, endpoint request or inference to paint a row. Download activity is observed on the existing completion and learning transfer owners only while a real admitted transfer holds its destination. No long-running poll is installed. Cancellation and window retirement join in-flight scans even when an adapter ignores cancellation.

The application shutdown owner must await `WelcomeWindow.RetireForAsync(host)` on the UI dispatcher before disposing the shared host/model managers. Ordinary window close uses the same retirement. The snapshot consumes the existing `LearningExplanationSnapshot()` backend, URL and model, so the separately owned explanation endpoint settings can project their active profile without a new readiness owner. Connection failures not exposed as persistent task-owner state cannot be inferred from a syntax-only endpoint check; a configured endpoint is not a connectivity claim. The first-use wizard's own observed completion failure is reflected while that operation belongs to the window. Windows has no equivalent single Mac accessibility permission switch; the existing Windows permission page explains supported hosts rather than presenting a fabricated authorization state. The fuller learning showcase remains separate work.

Core source-policy tests, fake transfer activity and isolated catalog tests cover configuration, missing files, actual download lifetimes and cancellation. STA WPF fake scans cover the four states, routing, stale response rejection and close waiting for ignored cancellation. `welcome-readiness.png` is a 96-DPI component render inspected for hierarchy and readability; it is not physical desktop, accessibility, full-window or real-model acceptance. No user models, endpoints, clipboard or editors were used in tests.

The final page is the same `WelcomeDonePage` component used by the wizard, with a scrollable body and an independently anchored Finish/Back footer. A 560 × 640 WPF host uses the wizard's margins and theme, synthetic readiness data and the real page control. Additional 150%-scaled body renders at 560 × 640 and 440 × 450 verify that each row and the tray explanation can be scrolled into view and that both footer actions remain visible and interactive. The screenshot host substitutes the existing button style for the window-local Back link style; it does not create AppHost or model services. These offscreen renders are not physical desktop or accessibility acceptance.
